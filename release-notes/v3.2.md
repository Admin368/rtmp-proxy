# v3.2 — Dashboard redesign

Branch `v3.2` · based on `v3.1`

A visual and usability pass over the dashboard. Nothing about authentication, relaying or the
database changed — this release touches two files, `src/web/styles.ts` and `src/web/views.ts`.

## The look

**Monochrome, dark only.** There is no hue anywhere in the stylesheet: the palette is six greys
between `#0a0a0a` and `#f2f2f2`, and hierarchy comes from weight, spacing and contrast rather than
colour. The previous theme followed the operating system and rendered as a light-grey admin panel by
default; this one is a deliberate single design.

**State is carried by shape, not colour.** A live stream has a filled dot with a slow pulse; an
active key a solid dot; a paused key a hollow ring; a retrying relay a dim dot. That reads at a
glance without relying on green/amber/red, and it survives being printed, screenshotted or viewed by
someone who does not distinguish those hues.

**Quieter chrome.** Cards have a header strip, a body and an optional footer that holds the "create"
form, so each section reads as one object. Section titles are small uppercase labels rather than
headings competing with the page title. The page opens with a one-line status — *"1 stream live
across all accounts · up 4h 12m"* — instead of making you read a table to find out.

## The usability work

**Copy buttons on everything you have to paste.** The server URL, the stream key format, and — on
the screen where a new API key is revealed — the key itself and a ready-made OBS stream key. This
was the worst part of the old page: the one moment that matters, handing someone a credential they
must transfer into OBS exactly, was plain selectable text. Falls back to `execCommand` where the
clipboard API is unavailable.

**A real mobile layout.** Under 760px the tables stop being tables and become stacked records with
the column name above each value, so nothing overflows and nothing needs horizontal scrolling. The
dashboard is now usable from a phone, which is where you are when a stream drops.

**Clearer controls.** The restart permission was a ghost button reading "grant" that looked like a
label; it is now an obvious **Grant** / **Revoke** button. Destructive actions (Kill, Delete) invert
to white-on-black on hover so they are distinguishable from their neighbours without a red.

**Better information density.** Each live stream shows its masked name, source address, owner and
key label, uptime, bitrate, codec summary and relay target with state and retry count — the same
data as before, but grouped two-per-cell instead of spread across nine columns.

**Relative timestamps.** "2m ago", "3h ago", "12d ago" instead of `2026-09-08 07:27:37 UTC`. The
absolute value was never the question being asked.

**Empty states that say something.** "Nothing is streaming right now", "No API keys yet — create one
below to start streaming" instead of a blank row.

## Accessibility and polish

- Visible focus rings on every interactive element, and the layout is fully keyboard-navigable.
- The pulsing live indicator is disabled under `prefers-reduced-motion`.
- `aria-label`s on icon-adjacent and repeated controls (per-row role selects, quota and password
  inputs, copy buttons).
- The auto-refresh poll skips while the tab is hidden and while a button or input has focus, so it
  cannot yank a control out from under you mid-click.
- The sticky header uses a solid background rather than a translucent blur — on an all-black theme
  the blur bought nothing visually while forcing a compositing layer that some renderers paint
  incorrectly.

## Not changed

Every route, permission check, form action and API response is identical to v3.1. `streamRows()`
still renders the same fragment the `/api/streams/rows` poll returns, all interpolation still goes
through the escaping `html` tag, and the masking of stream names is unchanged.

## Upgrading from v3.1

```bash
git checkout v3.2
docker compose up -d --build
```

Nothing to migrate. No new configuration, no database change, no change to how encoders connect.

## Verified

Login, dashboard, key creation with the reveal banner, live-stream table with an active publisher
and relay, copy buttons, the validation-error banner, and the stacked mobile layout were all
exercised in a browser at 1180px and 390px wide. The `/api/streams/rows` poll returns correctly
escaped markup carrying the `data-label` attributes the mobile layout depends on.
