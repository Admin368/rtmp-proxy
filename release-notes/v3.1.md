# v3.1 — Dependency and toolchain refresh

Branch `v3.1` · based on `v3`

No behaviour changes. This release clears every known vulnerability in the dependency tree, moves
the project to pnpm, and puts the container back on a supported Node release.

## Before and after

```
pnpm audit (v3)     14 vulnerabilities — 4 high, 6 moderate, 4 low
pnpm audit (v3.1)   No known vulnerabilities found
```

96 resolved packages, none deprecated.

## What was vulnerable

Everything was transitive — nothing in the application's own code. The fixes came almost entirely
from bumping the two direct dependencies.

| Package | Was | Now | Severity | Advisory |
| --- | --- | --- | --- | --- |
| `path-to-regexp` | 0.1.7 | 0.1.13 | high | ReDoS in the backtracking path |
| `lodash` | 4.17.21 | 4.18.1 | high | via `node-media-server` |
| `ws` | 8.x < 8.21 | 8.21.3 | high | via `node-media-server` |
| `qs` | 6.11.x | 6.16.0 | moderate | `isBuffer` DoS + array-limit bypass in comma parsing |
| `body-parser` | 1.20.2 | 1.20.6 | moderate | size enforcement silently disabled by an invalid `limit` |
| `send` | 0.18.x | 0.19.2 | low | template injection → XSS, via `http2-express-bridge` |
| `cookie` | 0.6.0 | 0.7.2 | low | out-of-bounds character acceptance |

## Dependency changes

| | Was | Now |
| --- | --- | --- |
| `express` | 4.21.0 | 4.22.2 |
| `node-media-server` | 2.7.0 | 2.7.4 |
| `typescript` | ^5.0.0 | 5.9.3 |
| `@types/node` | 22.5.0 | 24.13.3 |
| `@types/express` | 4.17.21 | 4.17.23 |
| `@types/node-media-server` | 2.3.7 | 2.3.7 (unchanged; still current) |

One override is needed, in `pnpm-workspace.yaml`: express 4.22.2 pins `qs` at `~6.15`, which is one
release short of the 6.16.0 that fixes the two open `qs` advisories. 6.16 is API-compatible, so it is
lifted for every consumer.

### What was deliberately *not* upgraded

- **express 5.2.1.** Express 5 is available and our usage of the framework is small enough to port,
  but 4.22.2 closes every open advisory without a major-version migration. Express 5 belongs in a
  release where it can be the headline and get its own testing, not bundled into a security patch.
- **node-media-server 4.3.2.** v4 is a rewrite with a different configuration shape and session API.
  v3.1 stays on the 2.x line, where 2.7.4 already carries the patched `lodash`, `ws` and `send`.
  Moving to v4 is an application rewrite, not a dependency bump.
- **TypeScript 7.0.2.** Compiler only, no security exposure, and brand new. Pinned to the current
  5.x instead.

## Toolchain

**pnpm replaces yarn.** `yarn.lock` is gone; `pnpm-lock.yaml` and `pnpm-workspace.yaml` take its
place, and `package.json` pins `packageManager: pnpm@11.25.0` so corepack installs the right version
automatically. Both Docker stages now run `corepack enable` and `pnpm install --frozen-lockfile`.

**Node 20 → Node 24 (alpine).** Node 20 is past end of life. `@types/node` moves to the matching
24.x line, and `engines.node` is declared as `>=20`.

**Small script tidy-up.** `docker:build` / `docker:up` use `docker compose` rather than the retired
`docker-compose` binary, and `pnpm audit` is available as `pnpm run audit`.

## Upgrading from v3

```bash
git checkout v3.1
docker compose up -d --build
```

Nothing to migrate: the database format, the API-key contract, the ports and every environment
variable are unchanged. Existing accounts, keys and OBS profiles keep working.

If you build outside Docker, switch package managers once:

```bash
corepack enable
rm -rf node_modules
pnpm install
```

## Verified

The v3 smoke test was re-run against the updated tree: publish refused without a key, accepted with
a valid one and relayed to a test RTMP sink at the correct bitrate, dashboard kill dropping the
publisher, login accepted and rejected correctly. TypeScript compiles clean under 5.9.3 with
`@types/node` 24.

**Not verified:** the Docker image build — Docker is not installed on the development machine, so the
Node 24 base image and the `corepack`/pnpm build steps have not been exercised. That is the one
thing worth watching on the first deploy of this release.
