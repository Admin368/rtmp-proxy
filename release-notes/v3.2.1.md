# v3.2.1 — Works behind a path-prefix reverse proxy

Branch `v3.2.1` · based on `v3.2`

A fix release. v3.2 assumed it was served from the root of a hostname. Behind an nginx
`location /4000/`, every link, form and redirect it emitted escaped the mount point and 404'd.

## The bug

The proxy on the deployment box is a standard prefix-stripping mount:

```nginx
location /4000/ {
    proxy_pass http://localhost:4000/;   # trailing slash strips /4000
}
```

Requests arrive at the app with the prefix already removed, so `/4000/login` is served correctly.
But nothing puts the prefix back on the way out:

- `res.redirect("/login")` sends `Location: /login`. It is path-only, so nginx's
  `proxy_redirect default` — which only rewrites `Location` values starting with the `proxy_pass`
  URL — leaves it alone. The browser lands on `https://host/login`, outside the app, and 404s.
- Every `<form action="/keys">`, and the dashboard's `fetch('/api/streams/rows')` poll, had the
  same problem.

So the login page rendered, and signing in threw you out of the application.

## The fix

**`BASE_PATH`** — the path the app is mounted under, e.g. `/4000`. Every URL the app emits now
goes through one helper, [`u()`](../src/web/urls.ts), which prefixes it: all 17 form actions, all
7 redirects, and the poll URL. Empty (the default) means mounted at the root and behaves exactly
as before — verified byte-identical.

**The session cookie is now scoped to the mount point** — `Path=/4000` rather than `Path=/`. On a
host that serves several apps behind one name, a root-scoped session cookie was being sent to all
of them. This is a real fix, not just tidiness.

**`PUBLIC_HOST`** — the hostname encoders should use for RTMP. The Connect card and the
new-key banner were showing `rtmp://172.23.0.2:4001/live`, the *container's* address, because
`getServerAddresses()` enumerates local interfaces and inside Docker those are the bridge network's.
Nobody outside the container can route to it. Set `PUBLIC_HOST=stream.example.com` and the
dashboard advertises an address that works. Blank keeps the old auto-detection.

The boot banner now reports the mount point and uses the same resolved addresses, instead of
printing interface IPs that may be unreachable.

## Configuration

Both are optional and both default to the previous behaviour.

| Variable | Purpose |
| --- | --- |
| `BASE_PATH` | Path a reverse proxy mounts the dashboard under, e.g. `/4000`. Blank = root |
| `PUBLIC_HOST` | Hostname encoders should use for RTMP. Blank = auto-detect |

`docker-compose.yml` now reads them from a `.env` file beside it, so deployment-specific values
stay out of git. See [`.env.example`](../.env.example). `.env` is gitignored.

```ini
BASE_PATH=/4000
PUBLIC_HOST=main.maravian.com
```

Accepts `/4000`, `4000` or `/4000/` — all normalise to `/4000`.

## Trailing slashes

Both forms work on the deployment box — nginx answers a bare `/4000` with a `301` to `/4000/`,
which then redirects to `/4000/login`. Measured, not assumed. If your proxy does not do this, add:

```nginx
location = /4000 { return 301 /4000/; }
```

## Not changed

No change to authentication, the API-key contract, relaying, the database format or the UI design.
Existing accounts, keys and OBS profiles are unaffected.

## Upgrading from v3.2

```bash
git checkout v3.2.1
printf 'BASE_PATH=/4000\nPUBLIC_HOST=your.host\n' > .env   # only if behind a prefix proxy
docker compose up -d --build
```

Signing in again is required once: the cookie's `Path` changed, so the old one is not sent to the
new scope. It expires on its own.

## Verified

Run locally under `BASE_PATH=/4000` with `PUBLIC_HOST` set:

- `GET /` → `302 Location: /4000/login`; sign-in → `302 Location: /4000/`
- `Set-Cookie: ... Path=/4000`
- every rendered form action prefixed, poll URL `/4000/api/streams/rows` returning 200
- new-key banner and Connect card show `rtmp://main.maravian.com:4001/live`
- kill action in the live-row poll response prefixed correctly
- a real publish with a valid key accepted and relayed to a test RTMP sink, which received it

And with both unset: `GET /` → `Location: /login`, `action="/login"` — unchanged from v3.2.
