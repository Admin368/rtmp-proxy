# v2 — Session tracking and a modern container

Branch `v2` · tip `a189e12` · February 2025

A maintenance release. No change to how streams are ingested or forwarded — v2 is about being able
to *see* what the server is doing, and to build the image reproducibly.

## What's new

**A status page worth looking at.** The bare `<ul>` from v1 became a card layout showing, per
stream: start time, last activity, and computed duration. Boot logs and the page now list every
non-internal IPv4 interface, so you can read the right `rtmp://…` address off the console instead of
guessing which NIC Docker picked. The web server binds `0.0.0.0` explicitly.

**Sessions expire.** Session records gained `startTime` and `lastPing`, and a reaper runs every 30 s
to drop anything idle for more than 60 s. `donePublish` does not reliably fire when a publisher
disappears rudely — a pulled cable, a laptop going to sleep — and without this the status page
accumulated phantom streams forever.

**`GET /health`.** Returns `{ status, activeStreams, uptime }`. Suitable for a container health
check or an uptime monitor.

**Two-stage Docker build.** Replaces v1's `node:16` + `apt-get install ffmpeg` image that copied a
pre-built `dist/` from a developer's laptop:

- builder — `node:20-alpine`, `yarn install --frozen-lockfile`, `yarn build` from `src/`
- runtime — `node:20-alpine`, `apk add ffmpeg`, production dependencies only

TypeScript is now compiled inside the image, so the image can no longer disagree with the source.
ffmpeg comes from Alpine's package index rather than a large apt layer, and the final image is much
smaller.

**Pinned dependencies.** `express`, `node-media-server` and the `@types/*` packages moved from
`^x.y.z` ranges to exact versions. With `--frozen-lockfile` in the build, the same commit produces
the same image.

## Fixed

- Phantom streams no longer pile up on the status page after an ungraceful disconnect.
- The image no longer silently ships stale compiled output.

## Known issues

Carried into v3 and fixed there. Both are ordinary bugs rather than unfinished work.

- **The status page prints full stream keys.** v1 truncated the stream path to ten characters on
  purpose — in this design the stream name *is* the YouTube stream key. v2's rewrite dropped the
  truncation, so anyone who can reach port 4000 can read your key. There is no login on the page.
- **The idle reaper watches the wrong event.** `lastPing` is refreshed from `postPlay`, which fires
  when a *viewer* starts playing, not from the publisher's own traffic. A publisher streaming for
  hours with nobody watching still disappears from the status page after 60 s.
- **`docker build` is expected to fail.** Both stages run `yarn install --frozen-lockfile`, but the
  preceding `COPY package*.json ./` does not match `yarn.lock`. With no lockfile in the build
  context, `--frozen-lockfile` is an error. (Reasoned from the Dockerfile; not confirmed by a build.)

## Upgrading from v1

Nothing to do. Ports, the ingest URL and the stream-key contract are unchanged: publish to
`rtmp://<server>:4001/live/<youtube-stream-key>` and the stream is forwarded to
`rtmp://a.rtmp.youtube.com/live2/<youtube-stream-key>`.

The server is still unauthenticated — anyone who knows its address can publish through it. That is
what v3 addresses.
